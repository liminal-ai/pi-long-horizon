# Stage 6 Backfill And Maintenance Rollups

Date: 2026-05-12

## Scope

Stage 6 persists materialized token count records on maintenance artifacts generated by the async thread services. It prepares later allocation work, but it does not switch Thread View builder allocation, smart compact band selection, or generated session validation.

## Persisted Fields

Smooth turns now carry:

- `smooth.tokenCountMetadata`, scoped as `smooth_turn_materialized`

Chunks now carry:

- `chunk.smoothTokenCountMetadata`, scoped as `chunk_smooth_materialized`

Placeholder artifacts now carry:

- `placeholder.detailed.tokenCountMetadata`, scoped as `detailed_chunk_materialized`
- `placeholder.brief.tokenCountMetadata`, scoped as `brief_chunk_materialized`

The `chunk_smooth_materialized` scope was added because chunk smooth text is a distinct materialized representation from both per-turn smooth text and detailed/brief placeholder text.

## Backfill Behavior

Maintenance services recompute records from current text when generated artifacts are missing or stale:

- `ensureSmoothTurn` treats missing or mismatched smooth token metadata as invalid and rewrites the deterministic smooth state.
- `updateChunkState` maintains chunk smooth metadata as the operational threshold count.
- `ensurePlaceholderArtifacts` validates chunk smooth metadata before generation and regenerates detailed/brief placeholders when their materialized records are missing or stale.

## Counter Source

All new maintenance records are produced by the Stage 4 materialized representation counter:

- `source: "pi_heuristic"`
- `trustClass: "heuristic_estimate"`
- `representationHash` over the exact materialized text representation
- `sourceRevision` where source state is available

This preserves the Stage 5 policy boundary: PI heuristic counts are degraded evidence and are not accepted in strict mode for successful smart compact decisions.

## Not Yet Switched

This stage does not:

- switch Thread View allocation to metadata records
- change smart compact band allocation or selection
- call provider count APIs
- implement generated session validation or retry

Those remain later-stage responsibilities.
