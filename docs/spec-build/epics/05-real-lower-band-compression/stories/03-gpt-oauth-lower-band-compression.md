# Story 3: GPT OAuth Lower-Band Compression

### Summary
<!-- Jira: Summary field -->

Closed Chunks produce detailed and brief semantic output through the real GPT OAuth-backed inference path.

### Description
<!-- Jira: Description field -->

**Primary User:** Context Steward

**Context:** The steward maintains a PI long-horizon coding session whose active Thread View must retain useful long-range context after smart compact moves older conversation into detailed and brief bands.

**Objective:** After this story, when a Chunk closes with a ready conversation-only transcript, the system schedules asynchronous detailed and brief semantic generation through a dedicated GPT OAuth-backed compression provider. The Chunk close path does not block on model latency. Both bands read from the same conversation-only Chunk transcript. Provider failures produce explicit failed artifact state. Real provider-backed lower-band tests in the default non-E2E suite prove the path works.

**Scope:**

In scope:
- Async generation triggered on Chunk close
- Chunk close path does not block on model inference
- Dedicated lower-band compression provider using GPT OAuth
- Separate detailed and brief prompts from the same transcript source
- Compressed output need not preserve `>` / `●` markers (free-form prose)
- Runtime routing estimate using `ceil(chars / 3.5)` — not persisted
- Oversized input warning and truncation at 4,000 estimated-token ceiling
- Provider/network/auth/model failures produce explicit failed state
- Lean artifact storage (status + text + error + updatedAt only)
- Real provider-backed non-E2E tests proving the GPT OAuth path end-to-end
- Real provider-backed lower-band tests fail when OAuth config is missing or wiring is broken

Out of scope:
- Size-range retry and escalation behavior (Story 4)
- Smart compact readiness and catch-up (Story 5)
- Placeholder removal (Story 6)
- Formal eval or model comparison

**Dependencies:** Story 2 complete.

**Story type:** Orchestration

**Governing idea:** Closed Chunks with ready transcripts produce real semantic lower-band output through the GPT OAuth path.

**Acceptance evidence (manual calibration):** Representative conversation-only Chunk transcripts have been manually reviewed with generated detailed and brief outputs. Notes, logs, or captured examples are sufficient; an automatic quality score, eval dashboard, or model comparison report is not required.

### Acceptance Criteria
<!-- Jira: Acceptance Criteria field -->

**AC-3.1:** Closed Chunks trigger asynchronous detailed and brief generation.

- **TC-3.1a: Chunk close triggers generation work**
  - Given: A Chunk closes with a ready conversation-only transcript
  - When: close processing completes
  - Then: detailed and brief generation work is triggered asynchronously or by an alternate worker process
- **TC-3.1b: Chunk close does not wait on model latency**
  - Given: lower-band generation requires model inference
  - When: the Chunk close path runs
  - Then: the deterministic close path is not blocked on model response latency

**AC-3.2:** Detailed and brief outputs are generated by separate prompts from the same source transcript.

- **TC-3.2a: Detailed request uses detailed prompt**
  - Given: A Chunk has a ready conversation-only transcript
  - When: detailed generation runs
  - Then: the generation request uses the detailed-band prompt and stores the accepted output under the detailed band
- **TC-3.2b: Brief request uses brief prompt**
  - Given: A Chunk has a ready conversation-only transcript
  - When: brief generation runs
  - Then: the generation request uses the brief-band prompt and stores the accepted output under the brief band
- **TC-3.2c: Outputs do not derive from each other**
  - Given: both detailed and brief are generated for a Chunk
  - When: their source is inspected through available evidence
  - Then: both trace to the conversation-only Chunk transcript rather than one lower-band output deriving from the other
- **TC-3.2d: Compressed output need not preserve source markers**
  - Given: the provider returns prose or bullets without `>` / `●` markers
  - When: the output is stored
  - Then: the output is accepted as valid lower-band text

**AC-3.3:** Compression routing uses runtime estimates without storing them on source-truth records.

- **TC-3.3a: Routing estimate uses character count**
  - Given: A conversation-only Chunk transcript is ready
  - When: compression routing runs
  - Then: the system estimates routing size using character count divided by 3.5
- **TC-3.3b: Routing estimates are not persisted**
  - Given: compression generation completes
  - When: the Chunk's source-truth lower-band artifact state is inspected
  - Then: routing estimates and estimated token counts are not stored there
- **TC-3.3c: Oversized input warns**
  - Given: runtime routing estimates a Chunk transcript above 4,000 tokens
  - When: compression generation prepares the input
  - Then: the system writes a standard-error warning and truncates compression input for that generation attempt to the configured 4,000 estimated-token ceiling

**AC-3.8:** Provider, network, auth, or model failures retry and then produce explicit failure state.

- **TC-3.8a: Provider failure leaves output not ready during retry**
  - Given: detailed or brief generation encounters a provider, network, auth, or model error
  - When: retry attempts remain
  - Then: the output is not marked ready and the retry activity is logged
- **TC-3.8b: Exhausted provider failures store failed state**
  - Given: detailed or brief generation encounters provider, network, auth, or model errors until allowed attempts are exhausted
  - When: generation stops
  - Then: the lower-band artifact records failed status and the last error code or message

**AC-6.2:** Provider-backed tests exercise the real GPT OAuth-backed lower-band path.

- **TC-6.2a: Detailed provider-backed path runs**
  - Given: the local environment has required GPT OAuth configuration
  - When: the default non-E2E verification command runs the real provider-backed lower-band test
  - Then: it exercises real detailed generation end to end for a basic Chunk
- **TC-6.2b: Brief provider-backed path runs**
  - Given: the local environment has required GPT OAuth configuration
  - When: the default non-E2E verification command runs the real provider-backed lower-band test
  - Then: it exercises real brief generation end to end for a basic Chunk

**AC-6.3:** Provider-backed verification fails when required GPT OAuth setup is missing or broken.

- **TC-6.3a: Missing OAuth setup fails provider-backed verification**
  - Given: required GPT OAuth configuration is missing
  - When: the default non-E2E verification command runs the real provider-backed lower-band test
  - Then: the command fails rather than silently skipping the tested provider surface
- **TC-6.3b: Broken model wiring fails provider-backed verification**
  - Given: GPT OAuth configuration exists but lower-band inference wiring is broken
  - When: the default non-E2E verification command runs the real provider-backed lower-band test
  - Then: the command fails with an actionable provider error

### Technical Design
<!-- Jira: Technical Notes or sub-section of Description -->

#### Architecture Context

This story is the first point where Epic 5 crosses a true external boundary.
Closed Chunks with ready conversation-only transcripts should trigger semantic
lower-band generation through a dedicated GPT OAuth-backed provider path. The
compression service owns scheduling, transcript loading, and lean artifact
writes. The provider owns only completion execution for the requested lane.

This story deliberately stops before size-range retry/escalation policy becomes
the main axis of change. It establishes the real provider path, async
close-trigger behavior, explicit failure state, and the curated real-provider
tests in the default non-E2E suite that prove the lower-band path is not just a
mockable idea.

#### Build Strategy

Strategy: `full-staged-risk`

Reason:
- async close scheduling, provider integration, artifact persistence, and test
  gate creation all meet in one slice
- this story is easy to fake with a mocked provider and weak provider-backed
  coverage
- it sets up later stories, so a shallow implementation here multiplies risk

Risk Reminders:
- prove the close path returns before model latency completes
- keep the provider-backed test genuinely real and loudly failing when auth or
  wiring are wrong, without adding a separate integration runner layer
- preserve lean artifact state while still logging useful failure context

#### Technical Notes

- This story owns provider integration and explicit failed state, but it does
  not yet own the full size-range retry/escalation contract. Keep the boundary
  with Story 4 intact.
- The compression service chooses the lane; the provider executes the requested
  lane and returns text plus minimal completion metadata needed for logs.
- Integration logging should follow the established redacted external-failure
  format rather than inventing bespoke provider-error strings.

#### Anti-Shim Requirements

- Do not satisfy the real provider-backed gate with mocked provider behavior or
  a test that only proves a provider method was called.
- Do not silently skip the real-provider suite when OAuth config is missing.
- Do not persist routing, retry, or provider metadata onto source-truth artifact
  state just because it is useful during implementation.
